# 10 — Testing Strategy

## 1. Layers

| Layer | Scope | Tooling |
|---|---|---|
| Unit | pure functions: hashes/ids, `bsxml`, `bsverify`, `prjconf`, recipe parsers, `gen_meta`/`diffdepth`, expansion, constraints oracle, path classification, repo metadata generators, tag mapping | Go `testing`, table tests, golden files |
| Contract | every gRPC service against its proto with a fake store; consumer-driven tests for compat-edge → services | `buf` lint/breaking, grpc testing |
| Integration | one service with real PostgreSQL + MinIO + NATS in `testcontainers` | per service |
| End-to-end | full stack on `kind`, a Rails instance pointed at compat-edge, `osc` scenarios (checkout, commit, branch, submit/accept, build, log, binaries, publish, container push) | nightly |
| Parity | golden corpus replay against the Go stack and diff against recorded Perl responses; scheduler decision diff; publisher output diff | CI on every PR touching the component |
| Performance | scale targets from `00` with synthetic projects (Factory-sized shard, 5 000 simulated workers) | weekly |
| Chaos | kill scheduler replicas mid-check, workers mid-build, S3 unavailability, PostgreSQL failover | nightly |

## 2. The golden corpus

- Built from the Perl backend's own test fixtures (`src/backend/t/data/*`),
  the Rails test suite's backend interactions (`Backend::Test`), and a
  curated set of real-world project snapshots (donated or synthetic:
  links/branches with patches and conflicts, multibuild, aggregates,
  patchinfo/channel maintenance flow, kiwi/productcompose products, docker/
  helm/flatpak/appimage/arch/apk/debian packages, DoD, remote projects,
  services incl. obs-scm, every repotype).
- Captured as request/response pairs for every route in `06a` plus the
  resulting on-disk state (trees, `:packstatus`, `:meta`, `:full` listing,
  job XML, published tree listing and metadata files, signatures verified
  with the test key).
- Stored in a separate repository (`obs-ng-corpus`) with a manifest of the
  Perl commit used; regenerated by a script that drives a Perl backend in a
  container.

## 3. Parity rules

- XML: canonicalise then compare; element order compared strictly (the
  Perl output is deterministic); timestamps and server-generated ids are
  masked by schema-driven rules.
- Hashes: `srcmd5`, `xsrcmd5`, `verifymd5`, servicemarks, `metamd5`,
  `jobid` must be equal, never masked.
- Scheduler: for every package in the corpus after each injected event,
  the status code and error text must match; job `buildinfo` must match
  after masking `readytime`/`server` URLs.
- Publisher: the published tree file list, every metadata file (after
  normalising createrepo timestamps/`revision`), and signature validity
  must match.
- obs-build invocation: the constructed command line and the three control
  files must match the Perl worker's for the same job.

## 4. Definition of done for a task

Unit tests, the relevant contract tests, and the parity subset named in
the task pass in CI; coverage of the task's package ≥ 80 %; lints
(`golangci-lint`, `buf`) clean; docs updated.
